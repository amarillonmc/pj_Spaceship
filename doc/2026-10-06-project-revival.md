# 项目复活讨论与第一阶段记录

日期：2026 年 10 月 6 日，UTC。

本次确定的方向是：保留 RPG Maker 内容与素材，用独立客户端、服务端权威世界和 MySQL 重建在线运行路径。第一阶段已形成可运行原型，并验证了菜单期间世界持续运行、双客户端战斗与物品结算；完整大逃杀规则和全部旧插件兼容仍未完成。

以下按议题归纳当日讨论和实施结果，属于讨论摘要，不是逐字聊天记录。下一阶段建议另见[第二阶段原型与测试素材方案](phase-02-prototype-plan.md)，不能视作已经实现或已经确定的最终游戏规则。

## 项目背景与玩法目标

原项目希望通过 RPG Maker MV/MZ 的在线部署实现多人游戏，并在另一种表现形式下还原 DTS。团队改造了 MMORPG 插件，又叠加 ARPG 插件；基础菜单与界面交互引发端与端之间的状态不同步，成为继续开发的主要障碍。

原始多人插件来源由用户提供：[MMORPGMaker-MV](https://github.com/samuelcardillo/MMORPGMaker-MV)。本仓库包含团队修改后的代码。

这里的 DTS 不指定某个现成游戏版本，而是指大逃杀的核心机制：大规模地图中的探索、寻物、追杀、逃离，以及实时战斗、合成、死亡掉落、世界事件、禁区和多路线结局。

用户已积累约 4 GB 以上 RPG Maker 格式素材，希望继续使用。必须保留的是内容投入与编辑便利，而不是旧引擎的全部内部结构。用户明确允许全盘重写运行时，继续以 RPG Maker 安排地图和事件；自建远端编辑器与解释器也属于长期可选方向。

## 旧架构为何出现不同步

代码排查发现问题同时存在于显示生命周期、世界模拟、实体标识和数据权威性。替换数据库本身不能解决这些问题。

| 问题 | 现有代码依据 | 对多人游戏的影响 |
| --- | --- | --- |
| 收到移动包时，当前场景没有地图 spriteset 或处于战斗场景就直接返回 | [MMO_Core_Players.js](../js/plugins/MMO_Core_Players.js) 的 `player_moving` 处理 | 部分界面期间收到的移动更新没有应用，界面与网络状态相互耦合 |
| 世界与 ARPG 更新依附本地 RPG Maker 场景生命周期 | [MOG_ChronoEngine.js](../js/plugins/MOG_ChronoEngine.js) 及原地图场景代码 | 某个玩家打开菜单，可能改变其本地世界推进，而其他端仍在运行 |
| 旧多人 ARPG 模板用共享变量和复制事件表达玩家与攻击 | [Map026.json](../data/Map026.json)、[Map029.json](../data/Map029.json) | 变量更新不能可靠替代有身份、有时序、有结算规则的游戏实体和动作 |
| 临时事件删除通过 `_events.splice` 改变数组位置；远端玩家又依赖事件编号 | [MOG_ChronoEngine.js](../js/plugins/MOG_ChronoEngine.js)、[MMO_Core_Players.js](../js/plugins/MMO_Core_Players.js) | 事件身份与数组位置混用，存在编号错位、错误删除或更新其他事件的风险 |
| 原服务端接受客户端上报的位置、地图及部分角色数值，再保存或转发 | [map.js](../server/modules/player/map.js)、[player.js](../server/modules/player/player.js) | 缺乏统一判定移动、伤害、库存和死亡的权威世界，无法只靠广播保证一致性 |

讨论结论是：旧客户端可以修复局部丢包与菜单问题，但要承载稳定的多人 ARPG 和大逃杀规则，需要明确由服务端拥有世界状态。仅补几个菜单钩子不能证明整套多人机制正确。

## 内容兼容与引擎方向

RPG Maker 文件格式兼容与任意插件行为兼容是不同层次的工作。地图、数据库、图块和人物素材可以被新引擎读取；事件指令需要定义在线执行语义；插件脚本可能直接改写场景、全局对象和引擎方法，不能因为文件能读取就宣称全部兼容。

本次实际采用的路径如下：

| 内容 | 当日选择 |
| --- | --- |
| 地图和事件编辑 | 继续使用现有 RPG Maker 工程作为内容来源 |
| 浏览器端 | 独立 Canvas 客户端负责输入、地图和界面显示 |
| 世界状态 | 服务端负责移动、战斗、实体、物品和时间推进 |
| 原有素材 | 直接读取仓库 `data/`、`img/`、`audio/` 等目录，不复制整套资产 |
| 事件 | 新服务端解释器执行受支持指令；需要适配的脚本显式处理 |
| 旧插件 | 读取已知参数和内容标记，不运行任意旧 JavaScript |
| 旧工程 | 保留原客户端、插件和 `server/`；新增代码位于 `engine/` |
| 自建远端编辑器 | 保留为后续方向，本次没有实现，也不是验证在线玩法的前置条件 |

新客户端打开背包或合成面板不会暂停服务端，也不会停止网络快照接收。新事件、怪物和玩家使用明确身份，避免把本地事件数组索引当作跨端实体身份。

## 数据库讨论与最终选择

讨论涉及 RethinkDB、MySQL、SQLite 和直接文件存储。用户最终选择 **MySQL**，并在发现本机已有 MySQL57 服务后，明确选择为项目建立**独立本地实例**。

数据库的职责是保存账号、角色、库存、掉落和结算结果；实时世界推进仍由游戏服务端承担。静态内容继续使用 RPG Maker JSON 文件。文件存储适合作为编辑内容与配置来源，不承担需要原子结算的多人抢拾和库存交易。SQLite 可用于独立测试或较小的部署，但当前在线实现统一使用已选定的 MySQL，不再同时维护多种后端。

原数据库使用 RethinkDB 的 `users`、`banks`、`config` 等数据，相关代码仍在 [server/core/database.js](../server/core/database.js)。新路径使用独立表结构，未实施旧账号和存档的自动迁移。

独立实例配置：

- MySQL 8.4.11，绑定 `127.0.0.1:3317`，不安装为 Windows 服务。
- 数据目录为 `engine/.local/mysql-data/`；应用凭据保存在被 Git 忽略的 `engine/.env`。
- 启停入口为 `npm run mysql:start` 和 `npm run mysql:stop`，在 `engine/` 中执行。
- 原有 MySQL57 服务和其数据未改动。
- 数据库使用 InnoDB 事务、玩家行锁、操作请求编号和原子掉落／拾取，避免重复结算。

此归档不保存数据库密码、登录令牌或其他本机凭据。

## 当日验证结果

自动检查记录为：`npm test` 通过 38 项普通检查，默认跳过两个需要 MySQL 的测试入口；随后 `npm run test:integration` 启用真实数据库，报告 12 项通过，其中包含父测试组。此数字不能理解为 12 个独立浏览器场景。

已验证的主要行为：

1. 导入所有 30 张地图；HTTP 返回完整地图数据；27 张通过服务端传送，另外 3 张明确报告没有出生点。
2. 两个 WebSocket 客户端的快照和移动同步；伪造坐标、HP、金币、背包以及过期移动序号不能覆盖服务端状态。
3. 实际 PvP 攻击触发死亡和掉落；拾取、重复请求和两人争抢掉落不会重复发放物品。
4. 重新登录恢复位置、库存和死亡状态；真实重启独立 MySQL 后，角色、掉落和请求去重记录仍保留。
5. 延迟合成事务与事件奖励并发时不丢失奖励；保存失败不留下未提交的事件奖励；重复合成不会把新状态回退成旧结果。
6. 浏览器中打开背包期间，世界 tick 从 910 推进到 1376，禁区使 HP 从 544 降到 404。这验证了该测试场景下菜单与服务端世界时钟的分离。
7. 浏览器实际检查了 Rural 与 School Hall 画面、角色移动、旧装备修理事件的对话与 No 分支，以及 Curry Bread 合成。

检查并未覆盖每个地图事件、每个技能和全部插件行为，也未完成两个浏览器窗口同时人工操作、长时间稳定性、网络故障矩阵或多人容量测试。

## 当前仍存在的限制

- 没有完整对局生命周期、地图与掉落按局隔离、胜负结算、跨地图禁区计划及多路线结局。
- 数据库当前仅有玩家、请求去重和掉落等基础表；账号身份、局内角色和局外成长尚未完整分离。
- 个人事件条件页与共享敌人身份、AI 的一致语义仍需设计；不能依赖个人开关可靠创建或销毁全世界共用的怪物。
- 多人容器、世界唯一物品、共同推进的门与机关、队伍作用域尚未完整实现。
- Traits、TP、全部状态与增益、装备部位、技能目标范围及 Chrono 工具语义未全部兼容。
- 商店、载具、回合战斗和若干界面／表现指令尚未完整实现；不支持任意旧插件运行时。
- MZ 完整项目尚无回归样例；MZ Effekseer、插件专有素材布局和循环地图摄像机存在缺口。
- 实时世界主要在服务端内存中；角色周期保存与事务提交，不等于世界每一帧、所有事件与怪物都可在崩溃后原样恢复。
- 未实现自建远端编辑器、旧 RethinkDB 数据迁移、多进程世界管理和公开运营部署。

因此，当日交付应称为可运行的第一阶段原型。菜单导致世界停止和丢更新的旧耦合已在新路径中移除并通过针对性验证，但不能将其表述成完整 MMORPG 或对所有不同步问题的最终解决。

## 开发入口与后续衔接

启动、停止、开发测试按钮和配置说明见 [engine/README.md](../engine/README.md)。当日使用的本地入口为 `http://127.0.0.1:8098`；服务是否仍在运行取决于本机进程状态。

修改 RPG Maker 数据后，需要重启新引擎重新导入，再刷新客户端。继续保留原资产与事件，新增测试场景应优先复制为独立场景，避免覆盖原作者内容。

下一阶段应先让少量玩家完整完成一局，再扩展地图规模、兼容覆盖与编辑器能力。具体建议、素材复用表和验收条件收录于[第二阶段方案](phase-02-prototype-plan.md)。
